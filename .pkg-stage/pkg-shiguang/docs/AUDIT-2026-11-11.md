## 1. P0 — 阻断与安全（按处理顺序）

### P0-1　明文私钥 + 忽略规则缺失

**现象**
- `azure-key.txt.txt`（工作区根目录）：完整 `-----BEGIN OPENSSH PRIVATE KEY-----` RSA 私钥，无口令，注释为 `azureuser@SandboxHost-...`。
- `shiguang/infra/certs/privkey.pem`：TLS 私钥；同目录 `fullchain.pem`。
- 工作区根目录**没有 `.gitignore`**；`shiguang/.gitignore` 与 `shiguang/.dockerignore` 均未出现 `cert`、`pem`、`key` 相关规则。
- `git check-ignore` 证实两个私钥都 **NOT IGNORED**；且全项目几乎全部 untracked，remote 已配置到 GitHub。

**影响**：当前私钥**尚未入库**（`git ls-files` 只有 LICENSE），但只要执行 `git add -A && git push`，SSH 私钥和 TLS 私钥就会进入远端仓库；`privkey.pem` 还会随 docker build context 被发送。属于可直接导致服务器被接管的风险。

**修改方法**
1. **移出工作区**：把 `azure-key.txt.txt`、`infra/certs/*.pem` 移到工作区之外的受控目录（如系统 SSH 目录），权限 `chmod 600`；工作区只保留 `README` 说明与占位文件。部署时从该受控目录 `scp` 到服务器 `infra/certs/`，**不要回拷进工作区**。
2. **轮换判定**：若这两个私钥曾通过聊天、邮件、截图、网盘外传过，**必须轮换**（Azure VM 重新生成 SSH 密钥对并删除旧公钥；Cloudflare Origin Certificate 在控制台 Revoke 后重新签发）。若从未外传，至少完成第 1、3 步。
3. **补忽略规则**：新建根级 `.gitignore`（内容见附录 B），同时在 `shiguang/.dockerignore` 追加 `infra/certs`、`*.pem`、`*.key`、`azure/`。
4. **提交纪律**：首个完整提交用白名单 `git add <具体路径>`，**禁止 `git add -A`**；提交前跑 `git status --short` 与 `git check-ignore -v` 复核。

**验收**
```
git check-ignore -v azure-key.txt.txt shiguang/infra/certs/privkey.pem
git ls-files | grep -Ei '(key|pem|cert|\.env$)'   # 应无输出
```

### P0-4　包管理器混用，依赖不可复现

**证据**
- `package.json:6` 声明 `packageManager: pnpm@9.12.0`，存在 `pnpm-workspace.yaml`；CI `:38,40` 与 `Dockerfile.api:12`、`Dockerfile.web:10` 全部使用 `pnpm install --no-frozen-lockfile`。
- 仓库实际只有 3 个 npm `package-lock.json`（根 / api / shared），**没有 `pnpm-lock.yaml`**。
- 本机 `pnpm: command not found`；`apps/web/node_modules/.bin` 为空。

**影响**：每次安装都重新解析最新兼容版本，CI / Docker / 本机三者依赖树不一致，`--no-frozen-lockfile` 还会让锁文件缺失被静默放过；本地 `next build`、`next lint` 无法执行。

**修改方法**
```
corepack enable && corepack prepare pnpm@9.12.0 --activate
cd shiguang
rm -f package-lock.json apps/api/package-lock.json packages/shared/package-lock.json
pnpm install                 # 生成 pnpm-lock.yaml
git add pnpm-lock.yaml       # 必须提交
```
并把以下位置的 `--no-frozen-lockfile` 改为 `--frozen-lockfile`：
`.github/workflows/ci.yml:40`、`infra/Dockerfile.api:12`、`infra/Dockerfile.web:10`。

**验收**
```
pnpm -r typecheck && pnpm --filter @shiguang/web build

```

**① 生产 overlay 改法**
- `docker-compose.yml:61-62`：删除 `NODE_ENV: development`、`SEED_DEMO_DATA: "true"` 两行硬编码，交给 `.env` / overlay 控制。
- `docker-compose.prod.yml:34`：`COOKIE_SECURE: "${COOKIE_SECURE:-true}"` → `COOKIE_SECURE: "true"`（当前被 `.env` 的 `false` 插值覆盖，这是 HTTPS 下 Cookie 缺 Secure 属性的根因）。
- `docker-compose.prod.yml:38-39`：`ENABLE_DEMO_ACCOUNTS` / `SEED_DEMO_DATA` 显式写 `"false"`；演示期需要开启时由部署脚本用第三个 overlay 显式覆盖，不要继承开发 `.env`。

**② 无证书分支改法（注意不要直接套 prod overlay）**
`infra/nginx-ssl.conf:8-9` 引用 `/etc/nginx/certs/fullchain.pem` 与 `privkey.pem`，而 `docker-compose.prod.yml:55-57` 无条件挂载该配置。当前部署包**不含 certs**，所以「无证书时退回基础 compose」是有原因的，不能简单改成统一走 prod overlay，否则 nginx 会因证书不存在而起不来。
正确做法是把 HTTPS 拆成独立 overlay：
- 新建 `docker-compose.tls.yml`：只保留 `proxy` 的 `443:443` 端口与 `nginx-ssl.conf` / `infra/certs` 挂载。
- `docker-compose.prod.yml` 移除上述 TLS 卷与 443 端口，只保留生产强化（restart、资源限制、环境变量、不映射 DB/Redis/API 端口）。
- `deploy-app.sh`：有证书 → `-f docker-compose.yml -f docker-compose.prod.yml -f docker-compose.tls.yml`；无证书 → `-f docker-compose.yml -f docker-compose.prod.yml`（仍拿到生产值，且 nginx 只监听 80）。
- 同步修改脚本 `:110/:115` 对 `.env` 的 `COOKIE_SECURE` sed 逻辑，与 overlay 写死值保持一致，避免两处互相打架。

**③ 前端地址统一改法**
```ts
// apps/web/src/lib/api.ts:17
const BASE = process.env.NEXT_PUBLIC_API_BASE_URL || '/api/v1';

// apps/web/next.config.mjs:9
env: { NEXT_PUBLIC_API_BASE_URL: process.env.NEXT_PUBLIC_API_BASE_URL || '/api/v1' },
```
- 删除 `docker-compose.yml:79` 的 `NEXT_PUBLIC_API_BASE_URL` 运行期覆盖（Next 构建时已内联，运行期改无效，只会误导）。
- `.github/workflows/ci.yml:58` 的 web 构建步骤加 `env: NEXT_PUBLIC_API_BASE_URL: /api/v1`。
- `admin/dishes/page.tsx:19`、`profile/page.tsx:34` 已是 `/api/v1`，保持不变，但建议改为统一从 `lib/api.ts` 导出 `BASE`，避免以后再漂移。

**④ git 改法**
1. 先完成 P0-1 的忽略规则，再建首个完整提交。
2. 白名单提交：`shiguang/` 下的源码、配置、文档、CI、Dockerfile、`.env.example` / `.env.production.example`；**排除** `.env`、`infra/certs/`、`node_modules/`、`dist/`、`test-results/`、`tests/e2e/.auth/`、根目录 PPT/海报/部署包/私钥。注意 `apps/web/public/images/dishes/*.jpg` 是运行必需资源，**必须入库、必须进部署包**。
