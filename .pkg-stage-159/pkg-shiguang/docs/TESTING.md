# 测试说明

## 命令

```bash
pnpm --filter @shiguang/shared test     # 推荐引擎 + 订单领域单元测试（已实测 27/27 通过）
pnpm --filter @shiguang/api test        # 后端单元/集成测试（待补，见 PROGRESS）
pnpm test:e2e                           # Playwright 全流程（需服务已启动）
pnpm -r typecheck                       # 全量类型检查
```

## 已实现用例（`packages/shared/src/recommendation.test.ts`）

| 分组 | 覆盖点 |
|---|---|
| 权重与评分 | 权重和为 1、配置归一化、贝叶斯均分平滑 |
| 硬过滤 | 过敏原（字段 + 食材文本）、显式忌口、系统推断不参与、售罄/下架/非餐次、素食模式 |
| 冷启动 | 判定条件、反馈权重让渡、解释不编造历史 |
| **验收场景 C** | 初始推荐 → 2 星 +「有点油腻」→ 画像平滑下调 → 高油菜降幅大于清淡菜 → 清淡菜反超 → 理由含「偏油」 |
| 学习机制 | 离线补评影响更小、时间衰减向中性收敛、高分增强、3 星中性 |
| 多样性/场景 | 避免连续重复、清淡情境、空结果不随机兜底、分数有界 |
| 订单领域 | 分为单位计金额、价格快照、非法输入抛错、状态机、时段容量、取餐码核销防重放 |

## 待补用例（接口/集成）

登录与权限（未登录 401、越权 403、商户跨档口 403）、菜品查询与筛选、创建订单扣库存、并发下单不超卖、取消恢复库存与名额、取餐码重复核销拒绝、提交评价与重复评价 409、修改/删除评价后均分与画像一致、推荐结果随反馈变化。

## E2E 规划（`tests/e2e/student-flow.spec.ts`）

覆盖任务书要求的完整链路：注册/登录 → 口味问卷 → 获得推荐 → 菜品详情 → 加购 → 选时段 → 下单 → 商户确认/备餐/核销 → 五星 + 体感 + 短评 → 查看评价记录 → 检查推荐变化。

另有异常用例：未登录访问、角色越权、售罄、重复提交、重复评价、空评分、超长文字、特殊字符、移动端窄屏。
