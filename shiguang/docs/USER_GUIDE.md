# 用户手册

> 按角色分：学生 / 商户 / 管理员。每步写「点哪里、看到什么、出问题怎么办」。
> 对应版本：2026-11-15。

---

## 一、学生

### 1.1 登录

浏览器打开站点 → 点「登录」→ 填邮箱密码。

> **演示环境**：登录页下方有「体验账号」列表，点任一账号自动填入邮箱，密码统一由部署方提供（见服务器 `.env` 的 `DEMO_PASSWORD`）。

### 1.2 完成口味问卷（首次使用，约 1 分钟）

从「我的 → 口味设置」进入，3 步：

| 步骤 | 填什么 | 影响 |
|---|---|---|
| 基础 | 菜系偏好、主食偏好、喜欢的食材 | 「口味匹配」维度 |
| 口味 | 辣度忍受度、咸淡、油腻接受度 | 「这道菜你吃不吃得惯」 |
| 约束 | 预算区间、忌口、过敏原、饮食模式 | **忌口和过敏原是硬过滤** |

**两条铁律**：

1. **过敏原与忌口是硬性过滤**，之后任何推荐都不会出现这些菜
2. **系统推断永远不会覆盖你手动设置的内容**（你在个人页能区分「我设置的」和「系统推断的」）

**预算建议**：别设太窄（如上限 ¥5），会导致推荐为空。15–25 元是常见区间。

### 1.3 今天吃什么（核心）

首页点「帮我选这一餐」，出 **3 道菜**，每道都有：

```
香菇滑鸡饭  ¥14
你设的预算 15–25 元内 · 和你偏好的「米饭 + 微辣」一致 · 你上次给类似菜品打了 9 分
```

点「推荐依据」可看**权重与各维度得分**。

> **匹配度是算法估算的排序结果，不是精确概率**。

**三种调整方式**：

| 操作 | 作用 |
|---|---|
| 「换一批」 | 同条件下重新排序 |
| 场景标签 | 想吃辣 / 清淡一点 / 高蛋白 / 来点汤 / 便宜点 / 尝点新菜 |
| 切餐次 | 默认按当前时段判断，可手动切 |

**「便宜点」的实际效果**：预算上限压到 15 元，超出的一律不推荐（硬过滤，不是降权）。

### 1.4 看菜单与菜品详情

底部导航「菜单」→ 按食堂/分类筛选、搜索 → 点菜品看：

- 价格、档口位置（几楼哪个窗口）
- **辣度 / 油腻 / 咸度三个维度条**（0–5）
- 营养成分（估算值，非实验室检测）
- 过敏原
- 历史评价

### 1.5 点餐与取餐

**① 选菜加入清单**

**② 选档口与取餐时段**

> **一个订单只能含同一档口的菜**。跨档口请分开下单。

**③ 确认下单**

生成订单号 + 取餐码；库存扣减、时段名额占用。

> 演示环境是**到店付款**，下单≠已付款。

**重复点击提交**：自动去重（幂等键），只生成一单。

**④ 到店取餐**

报取餐码或出示二维码，由档口核销。核销后订单变「已取餐」。

**取餐码有效期**：到该时段结束。过期未取，系统自动关闭（状态「已过期」）。

### 1.6 饭后 10 秒反馈

订单完成后点「评价这一餐」：

**① 点星星**（1–10 分）

| 分数 | 含义 | 常用标签 |
|---|---|---|
| 1–3 | 差 | 太咸 / 太油 / 分量少 / 不新鲜 |
| 4–7 | 一般 | — |
| 8–10 | 好评 | 味道好 / 分量足 / 性价比高 |

**② 选几个体感标签**（可选）

**③ 写一句话**（可选，限 100 字）

**提交后的影响**：
- 该菜星级立即更新（贝叶斯平滑，单条极端评分不会刷榜）
- **体感标签会真实影响下次推荐**：比如选「有点油腻」，高油腻度的相似菜会被降权
- **评分可事后修改**

**限制**：同一订单同一菜品只能评价一次；24 小时内最多补评 3 条。

### 1.7 越来越懂你

个人页有**看板式的口味画像**，区分：

- **我设置的**：问卷里填的，系统不会覆盖
- **系统推断的**：从你的评价里学到的

可一键**重置推断**（不影响你设置的忌口和过敏原）。

### 1.8 隐私

- 账号可申请停用并撤销登录态
- 订单与评价作为审计记录按规留存
- 不收集手机号、地理位置、支付信息

### 1.9 常见问题

| 问题 | 原因 | 怎么办 |
|---|---|---|
| 推荐为空 | 预算过窄 / 当前时段无供应 / 今天菜单未发布 | 放宽预算，或切换餐次 |
| 时段选不了 | 已过截止时间（提前 15 分钟） | 换下一个时段 |
| 菜品显示售罄 | 库存扣完 | 换一道 |
| 登录后又回到登录页 | Cookie 被浏览器拦截 | 确认用 `http://` 不是 `https://`；清 Cookie 重试 |
| 取餐码核销失败 | 已核销过 / 已过期 / 不是这个档口 | 看订单状态 |

## 二、商户

### 2.1 登录与权限边界

用商户账号登录 → 进入商户视图。

> **只能操作被授权的档口**。访问其他档口的接口会返回 403（后端 `assertStallScope` 校验）。

### 2.2 发布每日菜单（开档前必做）

**后台 → 菜单管理**：

1. 选日期和餐次
2. 从本档口菜品里勾选今天供应的，设置排序
3. 设置库存 `total`（今天做多少份，扣到 0 自动售罄）
4. 设置取餐时段与容量（如 11:30–11:45 最多 20 单）
5. 状态改 `PUBLISHED` 发布，学生端立即可见

> **当前限制**：没有"一键复制昨日菜单"，每天要手动挂一次。这是下一步要补的功能。

### 2.3 接单 → 备餐 → 核销

**订单操作台**：

| 状态 | 操作 |
|---|---|
| 待取餐 | 点「开始备餐」→ 变「备餐中」 |
| 备餐中 | 等学生来取 |
| 核销 | 输入或扫码取餐码 |

**核销三条规则**：
- **一码只能核销一次**（重复提示"已核销"）
- 必须是**本档口**的订单
- 必须在**有效期内**

### 2.4 维护菜品

**菜品管理 → 编辑**，可改：

名称、价格、分类、描述、食材、标签、营养估算、辣度/油腻/咸度、过敏原、素食/高蛋白标记、库存、上下架。

**不能改**：所属档口（改档口要走管理员）、评分（由学生评价决定）。

### 2.5 评价分析

**评价分析页**可看：均分分布、体感反馈占比。

> **样本不足 5 条时不会自动生成经营建议**——数据太少时任何结论都不可靠。

### 2.6 停售与恢复

- **停售**：菜品管理 → 下架（`OFF_SHELF`）
- **恢复**：菜单管理里找到已停售项 → 上架

> **已知问题**：某些视图下停售的菜不在默认列表，需通过档口维度查询。找不到时联系管理员。

## 三、管理员

### 3.1 用户与角色

**用户管理**：改角色、绑定档口、停用账号。

> 只有绑定了档口的 `MERCHANT` 才能操作该档口的菜单和订单。

### 3.2 食堂与档口

维护食堂信息（位置、营业时间、公告）、档口归属。

### 3.3 评价审核

**评价管理** → 对违规评价点「隐藏」。

> **只影响展示，不改统计与画像**——隐藏的评价仍计入均分，避免通过隐藏刷分。

### 3.4 经营看板

按**营业日（上海时间）**、**档口**、**订单状态**聚合：

- 预约数 / 完成数 / 取消数 / 过期数
- 各档口排行
- 菜品评分

### 3.5 操作日志

记录：改角色、改菜品、审核评价。含操作人、时间、目标对象、变更内容。

### 3.6 公告

发布系统通知，学生端首页可见。

### 3.7 紧急暂停（重要）

**没有一键暂停开关**。找断新预约用以下两种方式之一：

| 方式 | 操作 |
|---|---|
| 改时段容量为 0 | 后台 → 取餐时段 → 当日所有时段 `capacity` 改 0 |
| 取消菜单发布 | 后台 → 菜单管理 → 状态改 `DRAFT` |

**已有订单仍可履约或取消**——暂停只阻断新预约，不阻断取餐。

**立即暂停的四个条件**（满足任一）：
1. 数据丢失（订单/库存/评价异常缺失）
2. 越权（商户能改别人档口、学生看到后台数据）
3. 负库存
4. 同一取餐码被核销两次且都成功

## 五、完整链路一图

```
学生                          商户                    系统
 │                             │                       │
 ├─ 注册 + 口味问卷 ──────────────────────────────────→ 生成 UserPreference
 │                             │                       │
 ├─ 打开首页 ────────────────────────────────────────→ 按口味/预算/忌口推荐 3 道
 │                             │                       │
 ├─ 加购 → 选时段 → 下单 ─────────────────────────────→ 扣库存、占名额、生成取餐码
 │                             │                       │
 │                             ├─ 备餐 ────────────────→ 状态 READY
 │                             │                       │
 ├─ 到档口报码 ────────────────┤ 核销 ─────────────────→ 状态 COMPLETED（一码一次）
 │                             │                       │
 ├─ 评价（10 星 + 体感）──────────────────────────────→ 更新菜品均分 + 微调画像
 │                             │                       │
 └─ 下次打开首页 ←────────────────────────────────────── 推荐已变化
```
