# 食光有数开发执行书

适用仓库根目录为 `E:/campus-life_sixth-group`，应用工作区为 `shiguang/`。本文件供接手的 AI 在本地实施、验证和记录进度。开发目标和预估工期见[后续开发路线图](DEVELOPMENT-ROADMAP.md)。任务编号表示依赖关系，周次用于排期估算。

**接手指令**　读取本文件与路线图，执行任务 00 后，从满足依赖的首个未验收任务开始。直接完成授权范围内的代码、迁移、测试和必要说明。每项交付后更新文末记录；环境暂缺时继续独立任务。若用户指定任务编号或截止阶段，以该范围为准。第 12 项的默认交付是试点准备包，真实试点由项目负责人另行安排。

## 三、阶段一 · 可重建与数据安全

### 00 · 盘点当前状态

- 在仓库根运行 `git status --short --branch`、`git ls-files`。检查上传源码和密钥路径各自的忽略规则，只记录路径及规则。查看工作区包脚本、锁文件、已应用迁移文件与工具版本。确认本轮可使用的测试环境和现有改动。
- 2026-11-12 编写本文件时，基础 Compose 配置和 Azure 部署脚本语法已实测通过，两个用户更新入口已有显式响应字段。`git ls-files` 仍只列出 `LICENSE`，上传模块仍被忽略，演示清库仍能从启动与部署流程触发。接手时以新的工作区证据为准。
- **完成条件**　形成一段基线记录，列出已通过项、剩余缺口、可用工具和待准备环境，注明已有用户改动。定位：[工作区入口](../README.md) · [路线图](DEVELOPMENT-ROADMAP.md)

### 01 · 建立干净检出与发布构建

- 将上传运行目录的 Git 忽略规则限定到正确路径，检查 Docker 构建上下文同样包含上传模块源码。建立源码清单，包含各 workspace、迁移、必要图片、环境模板、CI 与发布脚本。
- 按 `packageManager` 固定 pnpm 版本，生成并审查锁文件。CI、Dockerfile 和本地说明统一使用同一锁文件及冻结安装；从实际声明 Prisma Client 的 workspace 生成客户端并验证输出。GitHub Actions 从仓库根识别工作流，各应用命令在 `shiguang/` 执行。
- 验证本地开发可通过同源入口访问 API。校验开发、TLS 和 Tunnel 的合并配置，开发调试端口只在开发配置发布，生产按选定入口暴露。修正 Shell 文件的换行和打包清单校验，制品能关联到准确的源码版本。现有打包脚本写入固定的上级目录，从隔离副本运行打包验收，或先给脚本增加独立输出路径。
- **完成条件**　独立的干净检出或干净导出的候选源码可安装、构建并通过配置校验。解包后可按说明重建，清单包括迁移、上传模块和菜品静态资源，敏感文件检查通过。源码尚未纳入 Git 时，分别记录候选导出验证和干净检出状态。定位：[忽略规则](../.gitignore) · [现有 CI](../.github/workflows/ci.yml) · [API 镜像](../infra/Dockerfile.api) · [Web 镜像](../infra/Dockerfile.web) · [打包脚本](../scripts/package.sh)

### 02 · 隔离演示初始化并保护历史记录

- 移除容器入口、Azure 部署和正常发布流程中的自动 seed，盘点所有其他入口与文档。演示数据改为显式、可重复初始化，放在独立数据库中。让 seed 的依赖解析随 workspace 安装通过，使用测试账号和可重复的供餐日期。
- 生产配置采用安全默认值，启动校验 JWT 密钥、安全 Cookie、CSRF 和演示配置。已存在的演示特权账号使用可审查的处置步骤按明确身份停用并撤销会话。先在隔离副本验证该步骤的影响范围。
- **完成条件**　隔离库写入哨兵用户、订单和审计记录后，升级、再次部署和重启均保留其内容。演示初始化运行两次结果一致，危险生产配置被拒绝，停用的测试演示账号和旧会话无法登录或续期。定位：[seed](../prisma/seed.ts) · [容器入口](../scripts/entrypoint-api.sh) · [Azure 部署](../azure/deploy-app.sh) · [生产环境模板](../.env.production.example) · [认证模块](../apps/api/src/auth/auth.module.ts)

### 03 · 约束写入权限和返回字段

- 盘点角色、档口和数据所有权。优先修复菜品更新的运行时 DTO 校验，逐项映射字段。商户编辑自身档口，档口归属和关系变更走明确授权的入口。复核菜单、库存、订单、核销、上传、商户统计和管理员写接口。
- 复用已存在的用户响应字段投影，并检查相关端点只返回调用方所需字段。验证失效身份、跨档口、普通学生访问后台与额外字段输入；保留现有合法请求路径。
- **完成条件**　测试覆盖未登录 401、越权 403、无效或未声明字段 400，以及授权写入成功。跨档口和额外字段请求后，数据库数据与角色保持原值。资料、后台和错误响应的回归断言覆盖敏感字段。定位：[菜品模块](../apps/api/src/dishes/dishes.module.ts) · [用户模块](../apps/api/src/users/users.module.ts) · [管理模块](../apps/api/src/admin/admin.module.ts) · [全局校验](../apps/api/src/main.ts)

## 四、阶段二 · 业务与数据一致性

### 04 · 统一时间、餐次和时段校验

- 以 `Asia/Shanghai` 计算营业日、餐次与截止时刻，保留数据库日期字段的日期语义。推荐、菜单、取餐时段和结算共享规则。API 以取餐时段记录推导档口、日期和餐次；兼容旧请求字段时，对不一致值返回明确错误。
- **完成条件**　固定时钟覆盖北京时间跨日、早餐、午晚餐分界、截止前后，以及 API 运行在 UTC、客户端位于其他时区的场景。时段查询和下单对同一时刻给出一致结果，关闭和不匹配的时段被拒绝。定位：[共享订单规则](../packages/shared/src/order.ts) · [菜单模块](../apps/api/src/menus/menus.module.ts) · [推荐模块](../apps/api/src/recommendations/recommendations.module.ts) · [取餐模块](../apps/api/src/pickup/pickup.module.ts)

### 05 · 下单、库存、价格和幂等

- 在同一数据库事务内检查供餐状态、库存、名额和截止时间，使用条件更新和成交价快照。购物车价格变更时返回可识别的冲突，结算页展示新价格供学生重新确认。
- 幂等作用域包含账号与键，并记录规范化后的请求内容或其指纹。同账号同键同内容返回原订单，同键异内容返回 409，其他账号无法读取该订单。并发冲突后按幂等语义回读；仅对可重试的事务冲突有限重试。旧订单继续可查，历史价格按成交快照呈现。
- **完成条件**　隔离 PostgreSQL 测试用同一夹具同时发出 20 个请求。最后一份、最后一个名额各只有一个成功预订；同键同内容只有一条订单记录和一次扣减；失败事务没有留下部分扣减、通知或订单。定位：[订单模块](../apps/api/src/orders/orders.module.ts) · [Prisma 事务](../apps/api/src/prisma/prisma.service.ts) · [数据库模型](../prisma/schema.prisma)

### 06 · 取消、核销和超时

- 复用现有状态枚举和角色权限，整理状态迁移表及库存、名额、凭证的副作用。取消、核销和超时先在事务中条件更新原状态，再变更关联记录。取餐凭证的有效期、档口和一次性消费以服务端为准。已备餐订单的取消与可售库存返还分别定义，按既有业务规则或负责人确认的规则处理。
- 超时按对应取餐时段和业务截止时间判断，覆盖应关闭的待取餐订单。任务重跑或与人工操作相遇时保持一致，记录可追查的结果。
- **完成条件**　双取消只返还一次，同码并发只核销一次，取消与核销、超时与核销各只有一个终态。验证未来预约、过期凭证、跨档口凭证，以及操作失败后的库存和名额。定位：[订单状态](../packages/shared/src/domain.ts) · [订单模块](../apps/api/src/orders/orders.module.ts) · [取餐模块](../apps/api/src/pickup/pickup.module.ts) · [超时任务](../apps/api/src/tasks/tasks.module.ts)

### 07 · 评价、统计派生值和画像重置

- 将补评限频检查与写入放在可保证并发结果的流程中；同一已核验订单菜品的评价由约束兜底。新增、编辑、删除评价时，以当前评价集一致更新均分和画像。确定画像重置生效时间，并让排序中读取的历史反馈也遵循重置规则。
- **完成条件**　并发补评后符合现有 24 小时 3 条的约定。重复已核验评价返回约定冲突，更新和删除后的派生值与数据库重算一致。重置后新增或编辑评价时，重置前的反馈不会重新影响个性化画像。定位：[评价模块](../apps/api/src/reviews/reviews.module.ts) · [偏好模块](../apps/api/src/preferences/preferences.module.ts) · [推荐反馈加载](../apps/api/src/recommendations/recommendations.module.ts)

## 五、阶段三 · 推荐、界面和闭环验收

### 08 · 推荐条件、预算与解释

- 共用单菜与套餐的可售、库存、餐次和饮食筛选。使用已核验的饮食适用性，严格模式排除信息未知项；补齐标签来源和维护入口。套餐只在总预算内选择，无可行组合时提示缺项。单菜的当次预算与解释使用相同口径。
- 移除重复的场景降权，把后台权重和算法版本持久化并记录修改。构造固定夹具覆盖正反样例，包括清晨餐次、售罄、紧预算、含蛋菜与纯素条件、未知标注、反馈导致的排序变化。保留同餐次热门菜作为试点对照基线。
- **完成条件**　测试套餐总价始终符合上限，过滤结果与推荐解释一致。演示数据中可观察到预期的反馈排序变化。权重更新在服务重启后生效。定位：[共享算法](../packages/shared/src/recommendation.ts) · [推荐模块](../apps/api/src/recommendations/recommendations.module.ts)

### 09 · 学生、商户与管理端

- 学生端把推荐与结算串到同一餐次，补上售罄、时段失效、价格变化和会话失效的处理。停用与上传走统一客户端，保留 `FormData` 边界、CSRF 和实际 HTTP 错误处理。会话并发过期时合并刷新，按需重试一次；已提交写请求遵循原有幂等约定。
- 商户端提供按授权档口查询的管理列表，使停售记录可恢复。接单、备餐、待取餐和核销入口按实际状态展示。管理端核对档口授权和审计，日报先限定档口和上海营业日，再按订单状态在数据库聚合。补齐菜品搜索分页、评价 8–10 分筛选和切换筛选的缓存行为；近 30 天饮食记录以明确时间窗和按日聚合结果展示。
- **完成条件**　启用 CSRF 后实际验证停用、上传和续期。停用失败时页面保留并提示原因，结算重试只有一个订单。商户能停售再恢复，越权写入被拒绝，学生访问商户统计返回 403。用超过一页的菜单、评分 4/8/10、重复点击筛选以及含 501 笔订单、取消单和跨日记录的夹具核对搜索、过滤和统计。定位：[Web 客户端](../apps/web/src/lib/api.ts) · [结算页](../apps/web/src/app/checkout/page.tsx) · [菜单管理](../apps/web/src/app/admin/menus/page.tsx) · [经营统计](../apps/api/src/analytics/analytics.module.ts) · [饮食记录](../apps/web/src/app/history/page.tsx)

### 10 · 将完整流程纳入 CI

- 以可重置的本地夹具启动 PostgreSQL、Redis 和三种角色。CI 分层运行依赖安装、Prisma 校验与生成、类型检查、构建、单测、真实数据库集成测试和浏览器 E2E。使用确定性时钟、隔离测试账号和数据，为各浏览器项目分配独立订单和库存夹具，避免相互消耗。
- 在浏览器实际完成登录、选菜、下单、备餐与核销、评价和下一次推荐，断言库存、订单、凭证及推荐变化。缺少夹具或评价入口时让该用例报告失败。桌面与移动端分别记录结果。
- **完成条件**　从空测试环境跑完主路径与权限、并发、缺货、截止、重复核销等反向场景。保留 CI 运行或等价本地日志，报告失败步骤。定位：[测试说明](TESTING.md) · [Playwright 配置](../playwright.config.ts) · [现有 E2E](../tests/e2e/student-flow.spec.ts)

## 六、阶段四 · 预发布与试点准备

### 11 · 预发布、恢复和回退演练

- 选择团队实际使用的 TLS 或 Tunnel 入口。用隔离环境验证 HTTPS、Cookie、CSRF、权限和端口。区分进程存活与依赖就绪，记录 API 错误率、预约与核销失败、任务最后成功扫描时间和备份结果。
- 修复备份失败传播与恢复遇错即停。在新测试库和独立上传卷恢复数据库和图片，核对代表性记录及资源。演练旧应用版本与迁移后的数据库兼容；数据迁移问题准备向前修复步骤。记录发布版本、恢复耗时和回退检查结果。
- **完成条件**　从验证过的制品启动、走通 HTTPS 主链路、完成数据库和图片恢复，并有应用回退证据。缺少合适环境时标记具体未验证项。定位：[部署说明](DEPLOYMENT.md) · [备份](../scripts/backup.sh) · [恢复](../scripts/restore.sh)

### 12 · 整理试点准备包
